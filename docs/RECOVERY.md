# 故障恢复契约

这里的“无损”是：已封存代码、数据、评测结果、研究笔记、工具结果和会话 ID 不丢失；同一操作不因为重启而重复执行。未提交的模型输出、内存中正在生成的内容不属于已提交成果，可能重新生成。磁盘损坏需要备份恢复，不能由重试解决。

## 持久化顺序

1. 消息先进入 SQLite WAL，消息 ID 与路由决定唯一；工具调用由 `native_id + call_id` 标识。
2. Host 领取任务后先保存启动意图，再启动独立包装进程；包装进程记录自身和 DSH 子进程的 PID/出生标识。
3. 工具在中心登记执行意图、本地 fsync 意图后才执行；先 fsync 结果，再回传 Router。回传丢失可以从本地结果补账。
4. DSH 原生会话日志持久化输入、消息和工具历史。输入持久化成功后才确认消费；订阅信息只进入上下文，不代表新授权。
5. 恢复沿用 job、project、native Session、Python session、generation、request、evaluation 的原身份。只有进程 attempt 增加。

## 故障分类

| 故障 | 行为 | 恢复条件 |
|---|---|---|
| 模型网络/服务/额度不可用 | 持久化故障，@ 提醒，停留在原模型请求并延后重试 | 服务恢复；不读取 token 余额 |
| Router 连接断开 | Worker 保留现场；在途评测按原限制结束；暂停新工具和模型准入 | 中心可达且无未决副作用 |
| 原生进程退出 | Host 确认实际进程已退出，报告故障 | 同版本、同会话日志、无未决副作用后新 attempt 续接 |
| 执行机失联 | 标记最后已知状态，主动 @，不推断进程死亡 | 执行机重新上线并核对原进程 |
| 工具返回前进程被杀 | 有本地完整结果则补账；执行状态未知则停在 reconciliation | 核验原评测记录/清理状态，不能换 ID 绕过 |
| 连续非法开发结果/停滞 | 依据可信开发评测摘要告警，不把负面结果当模型宕机 | 人工/Worker 分析；不自动增加预算 |

已知 provider/控制面不可用期间记录可信等待区间。单研究员有效时间扣除其等待区间；整批准入时间只扣除所有活动研究员均不可用的交集，不能因为某一个研究员等待就暂停其他人的时间。上限不重置、不扩大。开发机突然断电而无法证明的空白时长不擅自补入预算；续接保留成果，必要时由人决定新的批次窗口。

Host 先证明旧进程已退出；PID 可能复用时使用进程出生标识。启动意图与进程标识之间的崩溃窗口保留为未知，不盲目启动第二份。控制器锁仅在所属旧 DSH PID 已确认退出时清理；锁属于别的进程或日志事务不完整时继续保留现场。

## 手动核对边界

当前自动恢复覆盖明确的模型错误、网络恢复、已完成且本地持久化的工具结果，以及无未决副作用的原生会话重启。评测容器仍在运行、清理状态未知、只提交了执行意图没有可核验结果、会话日志损坏等情况必须先核验，不能承诺自动续跑。报告会说明阻塞而不是创建替代研究。

已禁用框架 Worker 和自动 harness 修改。缺陷只汇报，版本修改须另行明确授权维护。运行中的研究绑定原版本摘要；订阅新消息、修改飞书配置、登记新版本都不会替换它。

## 执行端重新连接的自动处理

Host 每 3 秒核验原生子进程的 PID/出生标识、原 native Session ID 和本地心跳；Router 同时要求该 attempt 已成功访问认证 context 接口。连接连续稳定 6 秒且没有未决操作后，自动关闭本次失联事件并恢复断联前状态。核验期间 UI 显示「自动恢复核对中」，不会直接标为正常执行。

- 原生回合仍在运行：放开原执行流程的连接门禁，不创建另一个进程或回合。
- 原任务执行中但回合空闲：每个失联事件只持久化一条续接输入；关闭 App 或重启控制平面不会重复续接。模型须先核对原成果，已有业务/配置错误仍阻塞时报告并等待，不反复执行。
- 原来等待用户输入、模型服务、执行核对，或者人工暂停：保留原有约束，不把连接恢复当作这些问题也已解决。
- 原进程确实退出：沿用既有 Host 恢复协议核验本地日志、同版本和原操作结果后续接原会话。等待用户输入的已退出 Worker 在收到答复或明确继续后才重启。
- 在途/未知操作：等原始结果落账后自动完成连接恢复；30 秒后仍未结清则通过原群提醒核对，不换 ID 重跑。

恢复通知通过持久化 outbox 去重。每次真正的新失联有自己的事件编号，避免第一次恢复后后续恢复被去重掉。实现兼容升级前遗留的 host_lost：从已持久化的原 attempt 状态事件恢复语义状态，不推测任务已完成。

参数位于 `config/settings.json` 的 `recovery` 节；默认 stable_connection_s=6、native_heartbeat_timeout_s=15、pending_notice_s=30、auto_resume=true。电脑睡眠时没有计算能力；唤醒并恢复通信后进入上述自动流程。预算不重置，也不把无法证实的离线时长擅自补回。
